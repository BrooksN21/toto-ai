# Drawing 4947 NO BET Incident

## Impact

The first scheduled `run-drawing` execution completed without an operational
error but returned `NO BET`. It selected zero coupons, spent zero RUB, and left
the configured 4980 RUB bank unused.

## Root Cause

TotoBrief returned both `start_at = null` and `name_en = null` for all 15
events. API-Sports returned 1096 fixtures across the successful schedule dates,
including every target pair, but matcher v3 consumed only exact normalized
names or reviewed aliases. Cyrillic TotoBrief names therefore produced 0/15
matches and no provider-derived effective start times.

The earlier null-start correction made event time optional and expanded the
schedule horizon. It did not solve unseen cross-alphabet team names. Drawing
4945 appeared successful only after aliases for that drawing were manually
added, which was incorrectly treated as general acceptance evidence.

## Why Tests Missed It

Synthetic tests used equal names, populated `name_en`, or pre-reviewed aliases.
They proved fail-closed behavior, timing persistence, rollback, and deadline
safety, but no test replayed a new real TotoBrief target with null times, null
English names, and an unmodified API-Sports schedule. Multiple reviews checked
the same incomplete acceptance contract.

## Correction

Matcher v4 keeps exact and alias matching first. When both English names are
missing and both target names are Cyrillic, it may consume one transliterated
same-or-reversed pair only when:

- pair similarity is at least 0.74;
- each team similarity is at least 0.55;
- the lead over the second candidate is at least 0.15;
- the existing sport and known-time restrictions pass.

All other cases remain fail-closed.

Sanitized replay fixtures now preserve the actual provider schedule inputs:

- drawing 4947: 15/15 correct provider IDs and `eligibility=playable`;
- drawing 4945: the previous 13 correct matches and two safe misses remain
  unchanged.

This correction proves timing recovery on these two observations. It is not
profitability evidence, and the prospective coverage gate remains pending.

## Release Rule

External matching changes are not production-ready based only on synthetic
tests or reviewed aliases. They require at least one raw unseen-team replay,
one prior-drawing false-positive regression, and full collection-level timing
verification.
